# 决策交接摘要 · 商业化转向纯积分制(本轮对话)

> 用途:压缩本轮对话的关键决策与产出,供存档与下次快速恢复上下文。
> 一句话:**商业模式从"Paddle 订阅制"一路转向"纯积分制 + 线下激活码充值",经济模型整体重算,并起草了网页端过渡版协议。**

---

## 一、商业模式的完整演变轨迹(为什么会走到这里)

1. **起点(Paddle 订阅制)**:网页优先、面向海外 diaspora、Paddle 作 MoR 绕开大陆合规与结汇。已产出策划 V2 与施工提示词。
2. **转折 1**:Paddle 支付认证遇阻 → 决定改用**自有微信支付商户**、目标市场转为**大陆优先**。
3. **发现硬阻塞**:微信支付网页接入要求 **ICP 备案域名**(未备案提交 API 密钥被 `DOMAIN_NOT_FILING` 拦),而备案需**大陆服务器托管** + `.space` 后缀须查工信部批复列表;同时触发生成式 AI 备案、数据出境等全套大陆合规。**支付代码是小头,合规是大头。**
4. **转折 2(最终方案)**:放弃在线支付,改为 **纯积分制 + 线下激活码充值**——用户线下联系创始人转账 → 发激活码 → 服务内兑换。**这一步把 ICP、大陆托管、算法备案、数据出境整条阻塞链全部下桌,现有海外栈原样服务大陆用户。**
5. **复用既有资产**:激活码复用 Step 5 已验证的 `invite_codes` 服务端原子核销模式(复用模式、新建表);收款层做成 provider-agnostic,将来接真实支付只加 adapter。

## 二、已锁定的最终商业模型(纯积分制)

**核心原则**:免费与付费**功能完全一致**,只有积分多少的区别;**免费档目标 = 让用户完整走完一个学习目标,付费买的是第二、第三个目标**。撞墙点落在"想开第二个空间"。

**单一货币 · 无会员 · 无订阅 · 无在线支付 · 无月度重置。**

### 锁定数字(经《积分经济模型 V1》整体重算)

| 项 | 值 |
|---|---|
| 注册新手包 | **150**(进充值桶,因免费桶上限 100 会溢出) |
| 每日签到 | **+5 / 天**(原 10,为不压制充值降到 5) |
| 免费桶上限 | **100**(只决定"签到是否发放",不截断其他入账;**取消了月度重置**) |
| 邀请奖励 | **双边各 +50 积分**(原送空间,已改;邀请方累计封顶 250 / 5 次) |
| 建空间 | **50 积分**(覆盖访谈+摘要+路径;彻底单一货币,空间不再是收费杠杆) |
| 单元生成 | **10 积分** |
| 问 AI | **1 积分** |
| 空间硬上限 | **50**(纯防滥用) |
| 一个学习目标总价 | **≈ 340 积分**(建空间 50 + 24 单元 240 + 追问 50)——公开写在积分说明页 |
| 激活码面额 | **300 / 1000 / 2500 ↔ ¥9.9 / ¥29.9 / ¥68** |

**两个桶**:`free_balance`(免费所得,有上限、不过期、先被扣)/ `paid_balance`(充值所得,无上限、不过期、后被扣)。

### 关键结构性修正

- **取消月度重置**:旧设计里签到进周期桶、每月重置为 30,会销毁勤奋用户攒的积分(越勤快损失越大)。改为"免费积分不过期,只受上限约束"。成本闸从"定期没收"变为"到顶不发"。

### 两条待办尾巴

1. **用真实通义千问单价标定**单次建空间/单元/问 AI 的分摊成本 → 回填 `billing_config`,据此复核定价。**标定前不对外报价**(当前 ¥0.0135/积分是 OpenAI 时期的估算,通义可能显著更低,毛利可能从 55% 跳到 85%+)。
2. **退出线**:每周激活码核销超 10 笔或月流水超 ¥3000,就启动正式支付——别让人肉充值吃掉半年。

## 三、合规与主体边界(当前状态)

- **当前只提供网页版服务**(knowledgeverse.space);**App 未正式发布,冻结**,协议/IAP/商店合规全部留到发布前。
- **服务提供者定性**:当前阶段**仅由创始人个人提供网页端服务,不与公司(北京筑梦探索科技)关联**。收款为个人微信手工收款。
- **已知敞口(如实披露,非已合规)**:数据存于境外 Supabase(跨境处理)、提问发送给通义千问、ICP/算法备案递延。这些义务附着在"向大陆公众提供服务"上,不因"改成个人"而消失;个人经营还带来个税与个人收款风控问题。
- **App 发布时的遗留决策**:主体归属统一、iOS 上数字积分必须走 IAP(不能用线下充值绕开)。
- **App 内那两个协议占位链接**:当前**不要**接到网页版协议(主体/范围不一致),维持占位或不放。
